# ROADMAP — от мессенджера к агенту

Дорога целиком бесплатная: free-tier'ы + устройства участников. Каждый шаг
самодостаточен и не блокирует следующий.

## Шаг 1. Единый интерфейс узла (рефакторинг ядра)
Свести `_post/_get/_firebase*_post` и будущие транспорты к одному адаптеру:
`send / subscribe / health`. Firebase и HTTP становятся двумя равноправными
адаптерами одного интерфейса. Формат конверта и крипта не меняются —
совместимость не ломается.
- Бонус: приоритет пути решается по факту health, а не по константному
  `priority` (Render из РФ станет просто «путём, который сейчас недоступен»).

## Шаг 2. v7: почта-слоты
`msg_<chId>_<sendIndex>` вместо одного перезаписного ключа; приёмник опрашивает
по своему recvIndex; пропуски закрывает кэш ключей v6.4. Чистка сессии — по
счётчику создателя. Тест-каркас: сценарий «спам в темпе набора» (полевой баг
v6.3) и «чистка сессии не оставляет слотов».

## Шаг 3. Локальный узел-вкладка (peer-as-node)
Вкладка/сервис-воркер отвечает тем же API ящика локально + в LAN (mDNS).
Серверы из списка понижаются в статус семечек первой встречи.
- Критерий успеха: мессенджер/пинг работает в Wi-Fi без интернета.

## Шаг 4. Query-конверт (первый настоящий пинг-понг)
`{type:'query', hop, ttl}` прыгает по живым узлам; ответ — подписанный указатель
(источник + ts). Сборка ответов инициатором. Без исполнения кода на узлах.

## Шаг 5. Полевые испытания (повторять после каждого шага)
- Межрегион, WiFi ↔ mobile: текст, спам «ведром», звонок. (v6.3: пройден.)
- Чистка сессии → сканируй серверы/Firebase: не осталось ли слотов.
- LAN: запросы между двумя устройствами без интернета.

## Шаг 6. Robin Hood — лицо агента
UI/голос/эмоции — самое приятное и не блокирующее: своя шкура в этом репо,
когда ядро и навигатор начнут отвечать. Сначала нервная система, потом Character.
